# v0.20.1 마우스·터치 시점 및 잠금 수정

- 마우스가 있으면 1·3인칭에서 WASD는 카메라 방향 기준 전후좌우 이동이다. 이동으로 방향을 회전시키지 않으며 마우스로 화면과 캐릭터를 함께 돌린다.
- 터치 전용 기기에서는 기존 100°/s 한도·입력량 비례·부드러운 가감속 선회를 유지한다. 오른쪽 드래그 회전도 유지한다. 터치와 정밀 포인터가 함께 있으면 마우스를 우선하며, 실제 마우스 포인터 입력도 인식한다.
- 런 시작과 레벨업·상자·장비·경로/지역·스킬 교체 후 최종 선택의 클릭/키 입력으로 마우스를 잠근다. 연속 선택창 사이에는 잠그지 않는다. 선택을 공격으로 처리하지 않는다.
- ESC 잠금 해제/일시정지와 계속 플레이 버튼 복귀, 항공 시점의 자유 커서, 잠금 미지원 환경의 가운데 버튼 드래그를 유지한다. 브라우저가 요구하는 사용자 입력은 런 시작·최종 선택에 사용한 입력으로 충족한다.
- 이미 포인터가 잠긴 동안에는 별도 포인터 캡처를 요청하지 않아 실제 공격/가운데 버튼에서 발생하던 `InvalidStateError`를 방지한다.
- 락온·공격 중 방향 고정·저장 데이터·전투 수치·그래픽 품질은 바꾸지 않는다.

변경: `src/view.js` 입력 장치 판단·잠금 복구·이벤트 정리, `src/game.js` 이동/포인터 캡처 분기, `src/main.js` 안내·버전, 관련 테스트와 README.

검증: 단위 **234/234**, 관련 Chromium WebGL 브라우저 스위트 **10/10**, 프로덕션·독립 HTML 빌드. [검증 수치와 검사 목록](input-controls-verification.json).

새 브라우저 검사는 실제 시작 클릭·보상 클릭/숫자 키·후속 스킬 교체·상자·보스 장비·경로/지역 선택·잠금 중 검 적중·시점 전환·ESC/복귀·잠금 거부 시 드래그를 확인한다. 터치 시작·이동·선택은 실제 터치 이벤트로 검증하며, 터치 기기에 실제 마우스 포인터를 보내 전환도 확인한다. 기존 모바일 테스트의 시작 입력은 마우스 클릭 대신 터치 탭으로, 잠긴 상태의 메뉴 접근은 ESC로 맞췄다.

브라우저 검증은 Chromium/SwiftShader와 터치 에뮬레이션이다. 실제 iPad/Safari·블루투스 마우스의 기기별 잠금 지원은 추가 실기기 검증 대상이며, 브라우저/격리 iframe이 잠금을 거부하면 드래그 조작을 사용한다.

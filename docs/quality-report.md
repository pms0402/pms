# VOIDRUN v0.18.0 품질 개선 보고서

## 개선 전 확인한 문제

기준은 `c7494c8`의 v0.17.0입니다. [진단 기록](quality-audit.md)에 코드 근거와 실행 조건을 기록했습니다. 주요 문제는 적중 뒤에 시작하는 검 준비 동작, 즉시 사라지는 적, 둥근 몸통·눈에 의존한 몬스터, 단색 하늘과 지역별로 비슷한 장식, 작은 전투 글자/터치 영역, 대부분 같은 오실레이터 효과음, 중간 그래픽 옵션의 부재였습니다.

기존 GPU 관절 인스턴싱·이동 보간·PBR/HDR·장비 비교·보스 예고·패링 판정과 저장 이관은 유지했습니다. 강화 가격·경제·능력치·상자·스테이지/지역/변이/조합 콘텐츠는 축소하거나 재설계하지 않았습니다.

## 전투와 밸런스

자동 검격의 피해·주기·사거리·적중 횟수를 유지합니다. 판정을 지연하는 대신 직전 0.16초에 준비 자세를 만들고, 실제 적중 때 동작의 접촉 구간(t=.42)부터 베기를 이어 갑니다. 빠른 공격은 시각 동작만 묶고 실제 타격은 계속합니다. 준비 동작의 방향은 다음 베기 방향과 일치합니다. 잔상은 실제 검 끝에서 샘플링하고 잠깐 남았다가 사라집니다.

쓰러짐 복사본은 충돌·타깃·드롭·보상에 참여하지 않으며 원래 재질을 바꾸지 않습니다. 보스 복사본을 우선하고 품질을 낮추면 활성 수를 즉시 줄입니다. 일반 공격/피격 파티클이 가득 차도 중요한 패링/반격/조합 표시가 대체합니다. 위험 예고는 상태 링과 장식보다 높은 표시 순서를 사용합니다.

기존 완벽한 패링 0.16초, 방어 0.45초, 재사용 4초, 실제 시간 히트 스톱 약 0.1초, 충격파 반경 4m, 반격 2초/검 피해 250%, 보스 경직과 저항 규칙은 바꾸지 않았습니다. 새 시청각 표현으로 추가 피해나 연쇄 발동을 만들지 않습니다.

## 성능 측정

기준/변경판 모두 같은 시드·카메라·960×540 버퍼·높음·160마리 고정 군중을 사용합니다. 12프레임 준비 뒤 60 RAF 프레임을 측정하고 네 번 재시작/GC로 보유 메모리를 확인했습니다. 변경판 측정 때 다른 브라우저 테스트는 종료했습니다. GC는 측정 도구만 호출합니다.

| 측정 | v0.17.0 | v0.18.0 |
| --- | ---: | ---: |
| RAF 중앙값 | 916.7ms | 833.4ms |
| RAF 95백분위 | 1849.8ms | 983.3ms |
| CPU 시뮬레이션+제출 중앙값 | 6.3ms | 7.4ms |
| CPU 95백분위 | 12.3ms | 12.7ms |
| 드로 콜 | 174 | 178 |
| 삼각형 | 547,896 | 431,010 |
| 측정 끝 GPU 기하/텍스처 | 180 / 15 | 192 / 18 |
| 네 번째 재시작 후 JS 힙 | 30.92MB | 32.93MB |

삼각형은 **21.3% 감소**, 이 소프트웨어 환경에서 RAF 중앙값은 **9.1% 감소**, 95백분위는 **46.8% 감소**했습니다. 새 표면/하늘·상태와 LOD 선택 비용으로 CPU 중앙값은 1.1ms, 드로 콜은 4, 텍스처는 3 증가했습니다. 이 비용도 함께 기록하며 모든 지표가 개선되었다고 주장하지 않습니다. 4회 재시작의 기하는 194/194/195/197로 캐시 예열이 남아 16회 반복 검사를 추가했습니다. 모든 지역과 변이 표식을 명시적으로 예열한 뒤 기하 163개·텍스처 18장·배치 37개·LOD 원본 37개·소유 기하 305개가 일정했고, 해제되지 않은 CPU 포즈 복사본은 0개였습니다. 9~16회 힙은 약 29.8~30.1MB였습니다. [16회 원본 기록](quality/reset-stress.json)을 포함합니다. 무작위 변이에만 맡기면 특정 표식의 첫 업로드가 늦어져 초기 수치가 늘 수 있으므로 검사 fixture는 모든 표식을 명시적으로 포함합니다. 원본 수치는 [변경 전](quality/before-metrics.json) / [변경 후](quality/after-metrics.json)에 있습니다.

### 실제 렌더 비교

같은 시드·적 배치·시점 모드·뷰포트입니다. 3인칭은 의도적으로 추가한 어깨 오프셋 때문에 캐릭터 화면 위치가 조금 다릅니다. 경험치 10억은 선택 창이 뜨지 않게 한 테스트 fixture 값이며 실제 성장 수치를 바꾸지 않았습니다. 이미지를 생성하거나 보정하지 않고 실행 화면을 캡처했습니다.

## 보존과 검증 범위

저장 키와 진행 스키마를 바꾸지 않습니다. 효과음/배경 음량은 기존 설정에 값이 없어도 기본값으로 동작하고 조절할 때만 저장합니다. 영구 강화·지갑·기록과 기존 카메라/키 설정을 유지합니다. v0.17.0 태그 및 v0.16.0 고정 실행본을 보존합니다.

**단위 테스트 186/186, 고유 브라우저 스위트 28/28 통과**, 프로덕션/독립 HTML 빌드 통과. [개별 결과](quality/verification.json)에 최종 재실행을 포함한 스위트별 실행 기록이 있습니다.

새 검증은 준비/접촉 동작·즉시 피해/보상·쓰러짐 상한·상태 표시·지역별 WebGL 경로·세 품질 옵션·피격/초기화·모바일 뷰포트와 실제 오디오 신호/음소거/저장/음원 해제를 확인합니다. 기존 전투·조합·변이·보스·심연·경제·강화·인벤토리·성역/비밀 공간·모바일 입력·시점·배포/독립 HTML·구버전 검사를 유지합니다.

## 남은 한계와 추가 개선

- 16회 씬/런 초기화에서 자원 상한을 확인했지만, 실제 iPad Safari와 저사양 물리 기기의 장시간 플레이/발열/오디오 청취는 이 환경에서 검증하지 못했습니다. 모바일 검사는 Chromium 터치 뷰포트입니다.
- 캐릭터와 몬스터는 기존 절차적 관절 모델을 다듬은 것입니다. 전문 아티스트의 풀 스킨 리깅, 모션 캡처, 얼굴 표정·손가락 애니메이션, 천/머리카락 물리 시뮬레이션 수준까지 구현한 것은 아닙니다.
- 환경 장식은 비충돌 소품입니다. 기존 건물/지형 카메라 충돌은 유지하지만 얇은 나뭇가지 등 새 소품에는 개별 카메라 충돌체가 없습니다.
- LOD는 배치를 유지하기 위해 같은 원본을 공유하는 몬스터 중 화면에서 가장 큰 개체를 기준으로 공유합니다. 가까운 개체와 먼 개체가 섞이면 먼 개체도 더 높은 세부도를 쓰며, 개체별 최저 비용보다는 가까운 외형 보존을 우선합니다. 전환은 히스테리시스로 억제하지만 크로스페이드는 하지 않습니다.
- 배경음은 직접 생성한 환경음/드론이며 작곡된 음악·성우·현장 녹음 사운드팩은 아닙니다. 브라우저가 허용한 사용자 입력 이후 오디오를 시작합니다.
- 실제 한 런 전체의 난이도·성장 곡선을 인간 플레이로 재평가하지 않았습니다. 이번 변경은 수치 밸런스를 보존하고 자동 전투/진행 검증으로 회귀를 확인합니다.

## 회귀 검사에서 보완한 테스트 전제

저주 배율의 기존/신규 적 비교는 무작위 변이를 제외해 독립적인 배율을 비교합니다. 새 비충돌 장식 그룹도 `noStaticBatch`를 사용하므로 지형 가림 검사는 실제 메시만 읽습니다. 쓰러짐/상태/하늘/룬의 고정 기하를 포함한 일반 품질 예산은 180→200, 공유 표면 텍스처 3장을 포함한 전체 콘텐츠 예산은 52→55로 명시했습니다. 재시작 후 자원이 계속 증가하는지 확인하는 상대 비교와 다른 개체/이펙트 상한은 유지합니다.

모달은 위치를 움직이지 않는 짧은 투명도 전환을 사용합니다. 패링 스트레스 fixture는 한 JS 작업에서 군중 화면을 16회 제출하므로, DOM 입력 검사 전 1픽셀을 읽어 실제 렌더 완료를 기다립니다. 소프트웨어 GPU의 테스트 대기열을 비우기 위한 처리이며 실제 게임과 벤치마크에 강제 동기화·클릭·지연을 추가하지 않았습니다. 검 잔상 검사는 새로 샘플링한 점과 검 끝을 비교하고, 공격 준비와 타격 후 남는 잔상은 별도로 확인합니다.

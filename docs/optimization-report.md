# VOIDRUN v0.19.1 최적화·근접 교류·카메라 추적

기준 버전은 `v0.19.0` (`890ee94`)입니다. 이번 변경은 기존 수동 전투와 그래픽을 유지하면서 CPU 중복 계산을 줄이고, 근처 물체의 상호작용과 캐릭터 방향을 따르는 시점을 연결합니다. 저장 키·영구 강화·지갑·장비·해금·기록 형식은 바꾸지 않습니다.

## 카메라와 상호작용

1·3인칭은 캐릭터 루트가 바라보는 수평 방향과 화면 방향이 일치합니다. 3인칭은 캐릭터 뒤 중앙에서 이동 위치를 부드럽게 따라가며, 1인칭은 기존 눈높이와 팔/검 표시를 사용합니다. 마우스 잠금, 가운데 버튼 드래그, 모바일 오른쪽 드래그는 캐릭터와 화면을 함께 돌립니다. W/S는 앞뒤, A/D는 옆걸음이며 이동만으로 시선이 돌아가지 않습니다. 공격 중에는 기존 검격 방향을 고정하고 회복이 끝나면 대기 중인 회전 입력을 적용합니다. 위아래 시선과 3인칭 거리 조절, 벽·지형·방 경계 충돌, 항공 시점, 대기 화면 캐릭터 미리보기는 유지합니다.

물체를 실제로 이용할 수 있는 거리에서 화면 하단에 `[설정된 키] 대상 · 행동` 버튼을 표시합니다. 기본은 C이며 모바일은 안내를 눌러 같은 동작을 실행합니다. NPC는 3.2m, 비밀 입구는 3.5m, 야영지 시설은 3.4m, 방의 문/제단은 기존의 엄격한 3.2m 미만 판정을 사용합니다. 안내와 입력 처리는 같은 대상 판별 함수를 사용하며 기존 입구 우선순위를 유지합니다. 대화·선택·일시정지, 이미 사용한 물체, 보상을 아직 받을 수 없는 제단은 안내를 숨깁니다. 자동 개봉하는 수호 상자 등은 기존 조건을 유지합니다.

[3인칭 구도](optimization/desktop-third.png), [모바일 세로](optimization/mobile-390.png), [모바일 가로](optimization/mobile-844.png)에서 방향 추적과 조작 버튼/상호작용 안내 배치를 확인합니다.

## 최적화 방법

- 정적 벽의 위치를 격자로 분류해 통행/우회 계산은 근처 벽만 좁은 판정으로 검사합니다. 특수 반경은 전체 검사로 돌아갑니다. 실제 밀어내기는 기존 순서와 3회 반복을 유지하고, 멀리 떨어진 벽만 빠르게 제외합니다.
- 몬스터 메시의 렌더링 그룹 키를 약한 참조로 보관하며 재질·기하·그림자·레이어 변경은 다시 확인합니다. LOD 전환은 기존 캐시 수명과 폐기를 따릅니다. 원래 화면 밖 그림자를 유지하던 부위는 불필요한 구체/절두체 검사를 생략합니다.
- 관절 애니메이션은 기존 GPU 변형과 루트 이동을 계속 사용합니다. 바뀌지 않는 말단 메시의 로컬 행렬만 재계산하지 않습니다. 매 프레임의 월드 행렬·관절 포즈·모션 주기는 유지합니다.
- HUD는 실제 DOM 값과 달라질 때만 텍스트·속성·스타일을 씁니다. 같은 스킬 SVG 노드를 보존하며 아이콘 종류가 바뀔 때 교체합니다. 패링/상호작용 문구를 여러 UI 모듈이 번갈아 덮어쓰던 경로를 정리했습니다. 쿨다운과 키 재지정은 실시간으로 반영합니다.

해상도·품질 프리셋·원본 모델·재질·LOD 정책·그림자·파티클 한도·개체 수·피해·보상·전투/모션 갱신 간격은 줄이지 않았습니다.

## 측정

단일 프로파일 결과에 변동이 커서 별도의 교차 반복 측정을 수행했습니다. 이전/최종 빌드를 같은 브라우저의 두 페이지에 열고 실행 순서를 번갈아 바꿉니다. 각 장면은 난수·프레임 번호·생성 번호를 초기화하고 60회 준비 후 360회 실제 시뮬레이션·조준·월드 행렬·배치 준비와 6회마다 HUD 갱신을 진행합니다. 7회 중 첫 2회를 제외한 5회의 중앙값을 사용하며 CDP 샘플링/구간 래퍼와 래스터화는 제외합니다. 두 빌드의 최종 적 위치·체력·생존 수가 매 회차 정확히 일치하는 것도 확인합니다.

[교차 반복 원본](optimization/compare-cpu.json)의 CPU 준비 비용:

| 개체 수 | 이전 중앙값 | 최종 중앙값 | 감소 |
| --- | ---: | ---: | ---: |
| 15 | 0.520ms | 0.349ms | 32.9% |
| 25 | 0.611ms | 0.386ms | 36.9% |
| 160 | 2.693ms | 1.468ms | 45.5% |

아래는 병목을 찾기 위해 프로파일러를 붙인 단일 측정도 포함한 기록입니다. 두 측정은 준비 과정과 계측 비용이 다르므로 절대 시간을 서로 비교하지 않습니다. 실제 GPU FPS와 구분합니다.

[이전 원본](optimization/before-metrics.json), [최종 원본](optimization/after-metrics.json), [이미지 비교](optimization/pixel-comparison.json)를 보관합니다. Chromium/SwiftShader, 높은 품질, 고정 난수와 640×360 렌더 버퍼에서 동일한 15/25/160마리 장면을 사용합니다. 각 경우 60프레임 준비 후 실제 수동 액션 명령과 시뮬레이션·조준·월드 행렬·렌더링 배치 준비를 360프레임 진행하고 HUD는 6프레임마다 갱신합니다. CPU 루프 안에서는 래스터화를 하지 않습니다. CDP 프로파일러와 구간 측정의 비용이 포함되며 구간 시간은 서로 중첩됩니다.

| CPU 준비 비용 / 프레임 | 이전 | 최종 | 변화 |
| --- | ---: | ---: | ---: |
| 15마리 | 1.569ms | 1.452ms | 7.5% 감소 |
| 25마리 | 1.109ms | 1.257ms | 13.4% 증가 |
| 160마리 | 3.700ms | 3.413ms | 7.8% 감소 |

160마리의 360프레임 합계에서 벽 충돌은 413.7→272.6ms, 우회 계산은 320.2→100.7ms입니다. HUD의 전체 DOM 변경은 각 장면에서 3,576→226건(93.7% 감소), 자식 노드 변경은 1,686→16건(99.1% 감소)입니다. 40회 동일 상태를 갱신한 별도 검사는 스킬 HUD 변경 0건과 아이콘 노드 보존을 확인합니다.

단일 측정의 총 비용은 JIT·GC·호스트 부하·프로파일러에 민감하며 모든 장면의 속도 개선을 의미하지 않습니다. 별도의 정적 군중 렌더 24프레임에서 소프트웨어 래스터화의 중앙값은 633.3→666.6ms, p95는 1183.3→1333.4ms로 오히려 늘었습니다. 실제 GPU의 FPS 개선이나 모바일 발열 개선을 검증한 결과로 해석할 수 없습니다. 교차 반복 측정에서는 CPU 준비 비용의 감소를 확인했으며, 정적 장면의 GPU 처리량 개선은 이번 변경의 검증 범위가 아닙니다.

같은 군중 렌더에서 드로 콜 **176**, 삼각형 **387,652**, 기하 **175**, 텍스처 **18**은 이전/최종이 같습니다. [이전 화면](optimization/before-crowd.png)과 [최종 화면](optimization/after-crowd.png)의 평균 RGB 오차는 255 중 0.0126 미만, 차이가 3을 넘는 픽셀은 약 0.128%입니다. 시간에 따라 움직이는 환경 요소로 미세한 차이가 남습니다. 캐릭터/몬스터 외형과 애니메이션을 줄여 얻은 개선이 아닙니다.

재현:

```sh
npm test
npm run build
npm run build:standalone -- dist/VOIDRUN.html
npm run preview -- --port 5201 --strictPort
BASE_URL=http://127.0.0.1:5201 npm run test:follow-interaction
BASE_URL=http://127.0.0.1:5201 BENCH_OUTPUT=/tmp/voidrun-opt npm run benchmark:optimization
# 5200에서 이전 버전을 서비스한 뒤, 프로파일러 없는 교차 반복 비교
BASE_URL=http://127.0.0.1:5201 COMPARE_BASE_URL=http://127.0.0.1:5200 BENCH_OUTPUT=/tmp/voidrun-compare npm run benchmark:optimization
```

이전 버전과 비교하려면 `v0.19.0`을 별도 작업 디렉터리에서 빌드·서비스하고 같은 벤치마크를 해당 `BASE_URL`로 실행합니다.

## 검증과 한계

**단위 테스트 213/213, 고유 브라우저 스위트 31/31 통과.** 프로덕션·독립 HTML 빌드, 루트와 `/pms/` 배포, 격리 iframe도 통과했습니다. [초기 실행·수정 후 재검사·최종 빌드 해시](optimization/verification.json)에 결과를 남깁니다. 최초 실행의 카메라 구도 검사와 야영지 훈련 패링 실패를 함께 기록하며, 구도 검사는 상체 추적/전신 표시를 검증하도록 바꾸고 훈련은 실제 조준 방향을 정렬해 수정했습니다. 변경된 시점·근접 안내·시련 보상·야영지·전투·배포/단독 실행은 최종 빌드에서 다시 통과했습니다. 충돌 최적화는 기존 전체 검사 구현과 난수 좌표·벽 경계·격자 경계·다양한 반경을 대조하며, 이동 밀어내기 결과를 원래 3회 순차 처리와 정확히 비교합니다. 근처 안내는 거리·우선순위·사용 완료·모달·키 재지정·실제 NPC/시설/던전 동작과 모바일 탭을 확인합니다. 야영지 훈련 시작 시 캐릭터와 조준 방향을 함께 정렬하고, 시련의 실제 처치→보상 안내→장비 선택까지 검증합니다. 시점 검사는 실제 캐릭터/카메라 수평 방향의 내적, 이동 시 방향 유지, 공격 방향 고정과 회복 뒤 회전, 벽 충돌·일시정지를 확인합니다.

균형 수치 변경은 없습니다. 검/마법 피해·쿨다운·성장·보상·적 수를 유지합니다.

실제 iPad/Safari의 장시간 프레임·발열·터치 감각은 기기 검증이 남습니다. 기존 v0.16.0 고정 HTML의 SHA-256은 `e8867949d23b1319d9f111432b4ce02f6982fca30ea40d564bc76b1d31b019aa`로 유지합니다.

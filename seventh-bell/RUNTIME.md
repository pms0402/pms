# 0.16.0 · 멈춤 대응과 길목의 적

## 이미지와 실행 루프

iPad Safari에서 조금 움직인 뒤 멈춘다는 제보를 기준으로 이미지 수명을 점검했다. 이전 75개 PNG는 디코딩하면 약 450 MiB였다. 원본을 모두 붙잡은 채 처음 보는 행동의 셀을 이동 중에 만들고 있었다. 데스크톱 Chromium에서는 같은 이동만으로 멈춤을 재현하지 못했으므로, 실제 iPad의 정확한 중단 원인을 확정한 것은 아니다.

- 원본은 두 장씩 디코딩한다. 로딩 화면에서 모든 실제 스프라이트를 준비하고, 배경·컷씬 이외의 원본 비트맵은 닫는다.
- 투명한 여백만 저장에서 빼고, 기존 논리 좌표·크기·발 위치·무기 기준점으로 그린다. 그림과 애니메이션 장수를 줄이지 않는다. 기존 58개 표본은 최적화 전후 픽셀 해시까지 일치한다.
- 새 중간보스 7종을 포함한 유지 래스터는 약 144.4 MiB다. 이 값은 원본과 스프라이트의 픽셀 바이트 합계이며, 브라우저 전체 메모리나 iPad의 실제 메모리 사용량을 뜻하지 않는다.
- 실제 게임 렌더링은 재사용하는 작은 셀만 읽는다. 검사 도구용 정사각 캔버스 캐시는 16개로 제한한다.
- 프레임 처리 중 예외가 발생해도 다음 프레임 예약을 잃지 않는다. 진행을 저장하고 복구 창을 띄우며, 계속하기 또는 다시 불러오기를 제공한다. 정상 플레이 중 이 창은 보이지 않는다.

개발 포트도 Safari의 Fetch 금지 목록에 들어 있는 4190에서 4191로 옮겼다. 공개 사이트의 HTTPS 포트와는 별개다.

## 중간보스

| 장 | 적 | 전용 외형 |
| --- | --- | --- |
| 1 | 종을 삼킨 사냥개, 로크 | 종과 마구를 단 검은 사냥개 |
| 2 | 향로를 놓지 못한 자 | 밀랍 두건과 사슬 향로 |
| 3 | 슬래그 운반수, 돌렌 | 닫힌 철 가면과 슬래그 운반통 |
| 4 | 낱장 사냥꾼 | 접힌 종이 몸과 잉크 관절 |
| 5 | 왕실 결투감찰관, 세른 | 상아 가면과 반쪽 망토 |
| 6 | 폐선을 짊어진 등짐게 | 난파선 껍질과 닻, 등불 |
| 7 | 삼중추 파수기 | 세 개의 추를 단 네발 장치 |

7종은 각자 세 행동과 24장 보행을 사용한다. 준비 중 방향과 목표를 정하고, 타격 뒤에는 빈틈을 둔다. 실제 무기·발톱 끝 등록 데이터와 지형 차폐로 근접 판정을 검사한다. 투사체는 유한 거리에서 사라지고 검으로 깨진다. 일반 적과 동시에 공격할 수 있는 수의 제한도 공유한다.

기존 일반 적 141마리의 ID와 처치 기록은 유지하고, 중간보스 바로 옆의 배치만 안전한 실제 바닥으로 옮겼다. 시작점·체크포인트·보스 준비 구간에는 배치하지 않았다. 중간보스를 처치해도 체력이나 약병은 채워지지 않는다.

보상은 장에 따라 120~360동전, 경험치, 기술 점수 1이다. 기록과 짧은 유품 문장이 수첩에 남는다. 본편 보스 결과나 문 해금에는 관여하지 않는다. 처치와 보상은 저장되고, 사망·재접속 후에도 반복 지급하지 않는다. 스키마 12의 기존 저장을 보존한다.

## 검증

`npm test`는 260개 검사를 통과한다. 새 검사에는 21개 중간보스 행동의 실제 판정, 준비 중 무피해, 패링 뒤 반격, 배치·벽 겹침, 보상 중복, 기존 저장 읽기가 포함된다.

`test:runtime`과 `test:minibosses`는 Chromium 및 WebKit에서 실행했다. 실제 프레임의 이동·터치 공격, 이동 중 래스터 생성 0건, 강제로 주입한 단일 예외의 복구, 저장·재접속을 검사한다. 중간보스는 장별 제한 장비와 약병 세 병으로 공격·이동·패링·회복 입력만 사용해 모두 처치했다. 전투 도중 체력·위치·피해량을 바꾸지 않는다. 전투 검사는 주변 일반 적·함정을 분리한 장면이다.

실제 iPad 기기를 원격으로 조작한 검사는 아니다. WebKit의 iPad 화면·터치 조건 검증과 물리 기기의 장시간 실행 성능은 구분한다. 전용 시트는 실제로 포함돼 있지만, 짧은 타격 프레임의 관절 연결은 추가 수작업 여지가 있다.

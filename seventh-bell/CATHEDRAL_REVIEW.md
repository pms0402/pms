# 성당 전투 구간 · 0.16.2

범위는 성당 입구와 첫 승강 발판이 있는 회랑(`x=6140..7580`)이다. [전후 비교 화면](review-cathedral/index.html)은 0.16.1 커밋 `c987ac52`와 이번 수정에서 같은 저장·입력·카메라·공격 프레임을 촬영한 원본 PNG를 사용한다. 일곱 장면을 선택하고 슬라이더로 겹쳐 볼 수 있다. 비교 페이지의 이미지는 게임 시작 시 내려받지 않는다.

- 돌·발판·문: 새 64px 논리 타일을 사용한다. 성당의 푸른 회색 돌, 왼쪽 위의 밝은 모서리, 어두운 옆면을 따른다. 플랫폼은 충돌 사각형 안을 불투명하게 채우고 정확히 자른다. 승강 발판은 올라가도 같은 돌 재질을 유지한다. 입구 장식의 크기를 줄였으며 문 상호작용은 유지한다.
- 일반 수도사: 기존 24장 보행과 새 24장 준비·타격·회복 시트를 연결한다. 중립 몸 높이를 51월드 단위로 고정하고 셀별 발바닥·몸 중심을 등록했다. 공격을 끊으면 지팡이를 쥔 준비 자세로 복귀한다. AI 상태나 이동은 렌더러에서 수정하지 않는다.
- 타격: 기존 검 판정이 적중을 승인한 후, 검날 선분과 적 몸 경계의 첫 접촉점을 계산한다. 이 점에 픽셀 섬광과 새 금속 타격음을 함께 발생시킨다. 소리의 어택은 2ms다. 기존 히트스톱 길이(기본 타격 50ms, 콤보 내려찍기의 행동 정지 82.5ms, 낙하 공격 75ms)를 유지한다. 잔상은 강철색의 얇은 픽셀 띠로 바꾸고, 수도사의 위험 표시에는 기존 도달 거리·벽·안전 구역을 반영한다. 베인 일반 투사체는 두 갈래 파편과 섬광을 남긴다.

새 PNG 두 장은 이미지 도구로 제작한 스프라이트시트다. 수작업으로 모든 픽셀을 찍었다고 주장하지 않는다. 원본과 출처는 [assets/LICENSE.md](assets/LICENSE.md)에 기록했다. 실행 파일은 기존 무손실 아틀라스 6장에 합쳤다. 2,793셀과 배경 10장을 합친 이미지 전송량은 약 41.88MiB(매니페스트 포함 42.20MiB)이며 원본 PNG를 시작 시 가공하지 않는다.

## 확인한 내용

수정 전과 후에 실제 브라우저 키보드로 접근 → 패링 → 반격 → 기본 베기 → 내려찍기를 실행해 수도사 `e33`을 처치했다. 이와 별개로 1/120초 입력 드라이버로 적의 걷기 → 준비 → 타격 → 회복, 기본 콤보, 점프 후 낙하 공격을 재생해 같은 프레임을 촬영했다. 전투 중 적·함정·피해량·위치를 바꾸지 않았다. 촬영 프레임에서만 재생을 멈췄다.

Chromium과 WebKit 모두 다음을 통과했다.

- 세 입력 재생의 위치·속도·HP·스태미나·공격 시간·AI·적중·투사체 기록이 수정 전과 같다. 원시 JSON 해시도 일치하며, 기준 해시는 `tests/fixtures/cathedral-before.json`에 남겼다.
- 섬광은 몸 경계 안의 접촉점에 있고, 타격음 이벤트·히트스톱과 같은 업데이트에서 발생한다.
- 윗발판 `(6820,140,240,18)`의 렌더 픽셀은 충돌 경계 밖 0개, 안쪽 투명 구멍 0개다. 끝을 0.01단위 넘는 순간의 착지/낙하도 별도 확인했다.
- 실제 AI의 투사체를 기본 검으로 베어 없앴다. HP 손실 없이 파괴 효과와 소리의 시간이 일치한다.

`npm test`는 기존 검사를 포함한 268개가 통과한다. `npm run test:cathedral`은 위 브라우저 검사를, `npm run review:cathedral`은 일곱 장면 촬영을 실행한다. `BASE_URL`로 정적 빌드를 지정할 수 있다. WebKit은 `BROWSER_ENGINE=webkit`과 필요한 경우 `WEBKIT_PATH`를 사용한다.

이번 확인은 이 회랑의 시각 수정에 한정한다. 다른 장이나 보스의 그림을 전면 개편하지 않았으며, 실제 iPad 하드웨어에서 Safari를 실행한 결과로 표현하지 않는다. 기존 공격 판정·피해량·난도·지역 배치·체크포인트·저장 스키마는 변경하지 않았다.
